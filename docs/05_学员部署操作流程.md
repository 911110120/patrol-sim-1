# 部署报名与公网验收

需要公网展示的小组或个人通过 PR 提交镜像和运行信息。工作组统一部署并提供展示地址，学员负责验证公网演示。

## 1. 准备仓库和镜像

1. 从 [培训班模板仓库](https://github.com/Yhimhas/patrol-sim) 点 **Fork**，在自己的仓库开发并推送。已有独立仓库的小组可以继续使用它，可在 Fork 里提交一份指向实际项目仓库的报名说明，再从 Fork 发起 PR。
2. 按项目自己的构建流程发布公开的 `linux/amd64` Docker 镜像。默认使用 GHCR。把镜像包的可见性设为 **Public**，从发布记录复制完整镜像摘要。
3. 用摘要指定版本，提交形如 `ghcr.io/owner/image@sha256:<64位十六进制摘要>` 的地址。请记录容器内 Web 端口、需要的环境变量名称和一个可访问的验证路径。
4. 从发布的镜像本地启动并在浏览器里操作一遍，确认地图加载、机器人移动、页面状态和本组实现的功能。浏览器发往同站点后端的 API 应使用 `/api/robot` 这样的相对路径。若前后端分开部署，请配置浏览器可访问的 API 地址。

以下示例适用于单个 Web 容器，端口和镜像地址换成本组实际值。示例把容器的 `8000` 映射到本机的 `8080`，便于发现前端写死本地端口的问题。

```bash
IMAGE='ghcr.io/owner/image@sha256:替换为实际摘要'
docker pull --platform linux/amd64 "$IMAGE"
docker run --rm --platform linux/amd64 -p 127.0.0.1:8080:8000 "$IMAGE"
```

在浏览器打开 `http://127.0.0.1:8080`。若项目有多个容器，按本组运行说明启动，并在 PR 补充各服务的镜像摘要、依赖关系和对外入口。

## 2. 提交部署报名 PR

1. 在小组 Fork 创建 `deploy/<组名>` 这样的报名分支并推送。在 GitHub 点 **New pull request**，必要时点 **compare across forks**。Base 选 `Yhimhas/patrol-sim:main`，Head 选小组 Fork 的报名分支。标题写「部署报名｜组名｜项目名」。分支、Commit 和标题的具体规则见[项目需求](01_项目需求.md#培训班部署报名-pr)。
2. 填写上游仓库自动带出的[部署报名 PR 模板](https://github.com/Yhimhas/patrol-sim/blob/main/.github/pull_request_template.md)。每组一条 PR，保持 **Open**。已经提交的 PR 可以直接编辑原正文，补齐模板字段。
3. 简要介绍项目模拟的巡检场景，填写实际实现的核心功能和访客可以体验的操作。可附运行说明、分工、截图或演示视频，文档可以沿用自己的格式。
4. 留意机器人评论，有缺项就在原 PR 修改。公开 PR 中的环境变量只列名称。如需提供实际值，请用工作组指定的加密渠道提交，并附 **PR 编号**。

| 机器人结果 | 如何处理 |
| --- | --- |
| 通过 | Git、PR 和报名字段检查通过，公开 GHCR 镜像摘要可查且支持 `linux/amd64`。等待工作组部署并提供展示地址。 |
| 待补充 | 按评论修正 Git 或 PR 格式，或补齐报名资料。 |
| 待工作组确认 | 使用了其他镜像仓库，请工作组确认该镜像可匿名拉取、平台兼容。 |
| 暂未完成 | GitHub 或 GHCR 未返回完整的检查数据。编辑并保存 PR 正文可重试，仍无法核对时联系工作组。 |

## 3. 验证公网演示

1. 收到工作组提供的**展示地址**后，用浏览器验证首页、地图、机器人操作和状态反馈，再试一遍本组要展示的其他功能。
2. 验证通过后，把展示地址补进本组仓库的根 README「在线演示」。如有问题，把操作步骤和现象反馈给工作组。
3. 发布新版时，在原 PR 更新镜像摘要和变更的运行信息，工作组部署新版后再验证。

## 工作组操作

1. 将 PR 模板、检查工作流和脚本加入上游仓库的默认分支，并启用 GitHub Actions。已开放的报名 PR 在作者更新正文或推送提交时重新检查。工作流用同一条机器人评论汇总结果，PR 继续作为报名记录保存。
2. 根据报名为本组分配 `.10` 上的 Coolify 应用，按摘要配置镜像、容器端口和所需环境变量。额外容器、存储或依赖服务按报名说明配置。
3. 由工作组在 Coolify 发起部署，通过现有公网入口配置展示域名。确认首页和验证路径可访问后，将展示地址发给学员验收。
4. 学员更新原 PR 的镜像摘要后，工作组核对变更的运行信息并部署新版。
